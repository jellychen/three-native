# v3.8 MeshStandardMaterial / glTF PBR channel alignment

This version focuses on reducing the visual gap between the current renderer and three.js `MeshStandardMaterial` behavior for glTF assets.

## Main changes

### Geometry / shader UV sets

- Added `ProgramKey::hasUv2`.
- Added `HAS_UV2` shader define.
- Added `uv2` vertex attribute binding at location `15`.
- Generic mesh vertex shader now emits `vUv2`.
- `aoMap` and `lightMap` sample `vUv2`, matching the three.js/glTF convention.
- Procedural geometry generated by `GeometryFactory` now duplicates `uv` to `uv2` by default so AO/light-map tests work without custom geometry setup.

### glTF PBR import behavior

- `alphaMode=BLEND` now sets `transparent=true` and `depthWrite=false`.
- `alphaMode=MASK` now sets `alphaTest` and keeps depth write enabled.
- `doubleSided` continues to map to `Side::DoubleSide`.
- glTF normal texture scale is read from common Assimp raw keys and maps to `MeshStandardMaterial::normalScale`.
- `KHR_materials_emissive_strength` style fields map to `emissiveIntensity` when exposed by Assimp.
- Metallic-roughness texture sharing is normalized: if Assimp exposes only one of roughness/metalness, both slots share the same texture.
- The shader already samples roughness from G and metalness from B, so shared glTF metallicRoughnessTexture follows the expected channel layout.

### Texture metadata

- `Texture::uvChannel` records Assimp/glTF `texCoord` index.
- `Texture::scalarChannel` records scalar-map channel intent for future validation/debug views.
- Assimp texture wrapping and UV channel index are now captured when available.

## New test

```bash
xmake f -m debug --use_angle=false --enable_assimp=false
xmake -r
xmake run 31_standard_material_channel_lab
```

The test validates:

- shared metallicRoughness texture: roughness in G, metalness in B
- AO map using uv2
- normalScale variation
- transparent material depthWrite behavior
- IBL + directional shadow context

## Still not full three.js parity

Remaining high-priority gaps:

- true PMREM cubeUV filtering parity
- complete texture transform per texture slot, not only primary `uvTransform`
- exact WebGLRenderer transparent sorting and transmissive queue
- flatShading, wireframe, clipping, fog parity
- KTX2/Basis texture decoding
- broader real-model glTF extension validation


## v3.8.2 compatibility fix

- Added `HemisphereLight::skyColor` three.js-style API.
- Added `LightShadow::mapSize` three.js-style API while preserving `mapSizeX/mapSizeY`.
- Shadow rendering resolves both old and new map-size APIs.
